# 中創園區契約容量暨空調聯防（Smart-Energy-Dashboard）

| 檔案 | 用途 |
|---|---|
| `app.py` | Streamlit 戰情室畫面（只負責介面） |
| `forecast.py` | 需量預測引擎（app 與 auto_log 共用） |
| `demand_model.py` | 實測校正模型：每小時最大 15 分鐘需量 = 小時基準 + 氣象修正，含最壞情況（P95） |
| `calibrate.py` | 每週一（GitHub Actions）用「實測需量」＋前一天氣象預報重新擬合，寫入 `model/demand_model.json` |
| `weather.py` | 氣象抓取：Open-Meteo ECMWF + Visual Crossing 備援 |
| `calendar_tw.py` | 台灣上班日／假日判斷（含補班），自動取得當年與隔年行事曆 |
| `data/calendar_overrides.json` | 臨時變更（颱風假、公告調整）手動加在這裡，優先於線上資料 |
| `auto_log.py` | 每天 18:00（GitHub Actions）把真實氣象算出的預測寫入 Google Sheet |
| `get_weather.py` | 氣象署測站資料記錄 |
| `tests/` | `python -m unittest discover -s tests` |

## 行事曆
每天快取更新一次；線上資料不完整或連不上時，畫面頂端會顯示警告並暫以「僅週末休假」判斷，
此時請在 `data/calendar_overrides.json` 補上平日假日（`holidays`）或補班日（`workdays`）。

## Google Sheet 紀錄說明
`auto_log.py` 寫入的是**預測值**（氣象預報 + 預設參數：進駐率 100%、無場地租借、18:00 下班），不是台電實測需量。
新資料列的「資料版本」欄為 `v3-實測校正`（使用 `model/demand_model.json`）或 `v2-實算預測`（只用物理模型）；
該欄為空的舊列是早期的示意假資料。
氣象全部斷線時不會寫入。

### 預測與實測比對（第二個工作表）
同一次執行另把**明日逐時預測**寫進「預測與實測比對」工作表，一個預測時段一列
（07:00–18:00 每小時），欄位：日期、時間、星期、台電時段、契約上限、預測需量、**實測需量**、誤差。
實測資料請貼到「實測需量」工作表（日期｜時間｜需量 kW，每小時一列，需量填該小時內 15 分鐘平均需量的最大值），
比對表的「實測需量」欄會自動查同日同時段的值，誤差（實測−預測，正值代表低估）與誤差 % 也會自動算出。
兩個工作表不存在時會自動建立；同一天重跑不會重複寫入。

### 實測趨勢（儀表板分頁）
儀表板「實測趨勢」分頁讀上述三張工作表（唯讀），畫出每日日間最高需量（08:00–18:00）的實測與預測、
452／516 kW 警戒線，以及單日 24 小時的實測、預測與台電時段上限。整理邏輯在 `trend.py`。
實測空白（監控停機或保養）不補值。

## 實測校正模型
- 預測對象：每小時內最大的 15 分鐘平均需量（台電計費方式），07:00–18:00，分上班日／非上班日。
- 輸入：Open-Meteo ECMWF 明日逐時氣溫、濕度、雲量、日射、降雨（每天 18:00 拿得到的預報）。
- 夏月平日 16:00 起磁浮全關的效果（實測約 75 kW）單獨處理，非夏月不會沿用夏天的低值。
- 側邊欄的活動、進駐率、兵推調整，以原物理模型的差值疊加在校正預測上。
- 「最壞情況」= 預估最高 + 過去 95% 日子的突波量；即時門檻：預警＝契約 90%（與現場 call 報一致），降載＝上限減 36 kW，解除＝上限減 66 kW；值班於中央監控手動調降磁浮。
- 每週一自動重新校正（近期資料權重較高，半衰期 21 天）；誤差異常（>60 kW）時保留舊模型。
- 手動重跑：Actions →「每週自動校正需量模型」→ Run workflow。
